## What this **does not** prove

- A GitHub-hosted Actions runner has a persistent live Beads database. It does **not**; this experiment uses a time-limited artifact and explicit restore.
- Two distributed concurrent consumers can independently **commit to the same durable state** without serialization; the source artifact is immutable per run and the consumer's subsequent changes are only in the consumer-run workspace/result, not fed back into the producer artifact.
- ChatGPT Web autonomously discovers or wakes to pending obligations; the second run was deliberately launched after selecting an exact prior result.
- Permanent archival of Dolt history in the Tecnotron SOT; Product authority, acceptance, TaskCycles, merge, review or `UNKNOWN` resolution.
- A permanent service, multi-host network server, automatic source-ref dedup, zero-maintenance cross-run continuity or an adopted architectural decision.

## Working disposition and future adoption evaluation

**Actions is a qualified execution/restore alternative** to the existing local sequential Beads binding for these bounded experiments. **Execution surface and durability owner are different choices**: use Actions or local depending on availability/compatibility, but do not treat short-lived Actions artifacts as authoritative long-term operational state. A truly shared persistent inbox requires either a qualified durable remote Dolt repository/service, a properly reconciled Git/Transport-backed snapshot with single-writer constraints, or an explicitly host-bound local store. Existing GitHub Projects still owns ordinary Product planning projections. Evaluate only the minimal viable durable state binding before moving any Product consumer to Beads.
