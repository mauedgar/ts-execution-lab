## Adoption implications

**Qualified empirically:** native Beads/Dolt on real GitHub over HTTPS with ephemeral Actions token can own a persistent experimental operational store without custom binary snapshot packing; fresh independent Windows runs can restore; two concurrent writers are protected by non-fast-forward ref semantics; a loser remains an unfinished obligation and can be reconciled from exact durable source after independent readback. This supports Actions as a **stateless execution surface**, with GitHub's native `refs/dolt/data` as a **distinct persistent store**, and does not require local host presence for these trials.

**Not qualified / constraints:**
- Native GitHub `refs/dolt/data` is a **repository-global** ref. Current `ts-execution-lab` ref is research-only; an eventual operational owner/isolation/ACL must be selected, never silently share Product repo writes.
- A competing writer's uncommitted local state is discarded when its Actions runner exits. Recovering its source requires durable original IDs/receipts; automatic merging of native divergence by `bd dolt pull` is **not tested**. Never infer that all accepted tasks were published from workflow SUCCESS.
- `SOURCE_REF`/native `--external-ref` are not guaranteed unique under concurrent create; fixed deterministic `--id` and conflict readback remain candidate safeguards, not automatic Product idempotence.
- `GITHUB_TOKEN` scopes are material: `contents:read` gives publisher **403**; need per-job `contents:write` for authorized experimental state writes, not any new Product authority gate.
- Windows native Dolt bootstrap can hit Git cache path **Filename too long** for deep work directories. Using an isolated short runner path recovered successfully; binding requirements should record the path-depth limit.
- Unknown-after-dispatch when acknowledgement/receipt is lost is **not yet separately qualified** for remote native Dolt; no blind retries.
- The original Action receipts and artifacts have provider retention. This authored verified Git report retains identities and findings, not full original binary local candidate state. Git native Dolt ref itself is a persistent experimental repo ref, not a separate verified off-site backup.
- No proven automatic chat wake/inbox query at ChatGPT task completion, no local-native Github credentials qualification, no remote multi-tenant ACL guarantee, no provider-failure/recovery/DR, no bounded cost/latency SLO, no real Product handoff cycle, no GitHub Projects sync or physical State Kernel replacement.
- No active Tecnotron Product TaskCycle, Developer grant, IR, Phase 2 or candidate was modified or initiated here. Tecnotron's repo SOT and `NONE/CONFIRMED/UNKNOWN` invariants remain externally owned and must be evaluated for any proposed component absorption.

**Current research recommendation:** Continue evaluating **native Git/Dolt first** as a low-custom-code operational dependency/index/backlog substrate; prefer stateless Actions or available local command execution according to binding. Next test remote native ambiguous-effect reconciliation and true recovery of a durable cross-module handoff through independent agents/surfaces. Compare current real Product consumer inventory before deciding what to narrow/remove; no new scheduler, server, gate or role is justified by these trials alone.
